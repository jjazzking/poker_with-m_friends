# ♠️ 친구들과 홀덤 (Poker with Friends)

링크 하나만 공유하면 친구들이 **동시에 접속해서** 실시간으로 텍사스 홀덤을 칠 수 있는 웹사이트입니다.
화면은 별도 빌드가 필요 없는 순수 HTML/CSS/JS 이고,
게임 진행은 **중앙 서버(Node + WebSocket)** 가 맡습니다.
화면은 GitHub Pages 같은 정적 호스팅에 올리고 서버만 따로 띄우는 구성이 기본입니다.

## 요청한 기능

| 요구사항 | 구현 |
| --- | --- |
| 링크로 동시 접속 | 방을 만들면 `room.html#<6자리 코드>` 링크가 생기고, 접속자 전원의 화면이 중앙 서버를 통해 실시간으로 동기화됩니다. |
| BB 금액 / 최초 스택을 방 만들 때 결정 | 로비의 "방 만들기"에서 BB·SB·최초 스택(50/100/200/300BB 프리셋 포함)·최대 인원·액션 제한시간을 지정합니다. |
| 베팅 금액을 BB 기준 / 금액 기준 모두 지원 | 액션 바의 `BB 단위 ↔ 금액 단위` 토글. 입력값은 실시간으로 서로 환산되어 표시되고, 슬라이더·퀵버튼(최소·2BB·3BB·1/2팟·팟·올인)도 함께 동작합니다. |
| 카드 랜덤 배분 | 매 핸드마다 52장 덱을 암호학적 난수(Node `crypto.randomInt` / 브라우저 WebCrypto) 기반 Fisher–Yates 로 셔플합니다. 홀카드는 본인에게만 전송되고, 다른 사람 화면에는 뒷면으로만 내려갑니다. |
| 실시간 완성 패 표시 | 액션 바 위에 **지금 내 패**가 계속 표시됩니다(프리플랍은 포켓 페어/수티드 여부, 플랍부터는 7장 중 최고 5장의 족보). 족보 이름은 크게, 그 패를 이루는 카드는 보드와 같은 크기의 카드로 함께 보여 주며, 테이블 위에서는 초록 테두리로 강조됩니다. 남의 패는 계산해 주지 않습니다. |
| 올인 쇼다운 | 올인에 콜이 붙어 더 이상 액션이 없으면, 보드를 깔기 전에 한 박자 쉬고 양쪽 홀카드를 먼저 눕힙니다. 그 뒤 남은 보드가 한 장씩 열리고 결과가 나옵니다. |
| 핸드 결과 화면 | 핸드가 끝나면 누가 얼마를 가져갔는지 화면 한가운데에 크게 뜹니다. 내가 이긴 판은 금색 트로피와 획득 칩으로 확실히 구분되고, 분할 승리·사이드 팟은 사람별로 한 줄씩 나옵니다. 몇 초 뒤 저절로 사라지고, 눌러서(또는 `Esc`) 바로 치울 수도 있습니다. |
| 방장 도구 | 상단 **⚙ 방장 설정**에서 블라인드 올리기 · 일시정지 · 강퇴를 할 수 있습니다. 블라인드는 핸드 도중에 바꾸면 다음 핸드부터 적용되고(배지에 `SB 1 / BB 2 → 2/4` 로 예약이 보입니다), 일시정지는 제한시간을 멈추고 다음 핸드가 시작되지 않게 하며, 내보낸 사람은 같은 링크로 다시 들어오지 못합니다. |
| 카드 애니메이션 | 홀카드는 테이블 중앙에서 각 자리로 순서대로 날아오고, 플랍·턴·리버와 쇼다운 공개는 카드가 뒤집히며 열립니다. 팟이 커질 때와 액션 문구에도 짧은 연출이 붙습니다. |

## 구조

```
  브라우저 (GitHub Pages 에서 받은 화면)
        │  WebSocket wss://<서버>/ws
        ▼
  중앙 서버 (Node)  ← 카드 셔플·베팅 판정·팟 정산·상태 방송을 전담
        │
        └─ 디스크에 방 상태 저장 (재시작해도 자리와 스택이 살아남음)
```

화면(정적 파일)과 서버는 **다른 곳에 있어도 됩니다.** 화면은 Pages 에, 서버는 Render/Fly 에 두고
빌드할 때 서버 주소만 알려 주면 됩니다.

> 서버 없이 도는 **P2P 폴백**(`?mode=p2p`)도 그대로 남아 있습니다. 다만 방장 탭이 곧 서버라
> 방장이 창을 닫으면 방이 사라지고, UDP 를 막는 망에서는 연결 자체가 안 됩니다.
> 급할 때 쓰는 비상용으로만 두는 것을 권합니다.

## 배포하기

### 1) 중앙 서버 띄우기

WebSocket 을 지원하는 곳이면 어디든 됩니다. `PORT` 환경변수를 읽고 `/healthz` 로 헬스체크를 제공합니다.

**Render** (`render.yaml` 포함 — 저장소를 연결하고 New → Blueprint)

```bash
# 배포 후 나온 주소를 확인
curl https://<앱이름>.onrender.com/healthz
```

무료 플랜은 15분간 요청이 없으면 잠들고, 다음 접속 때 40~60초쯤 걸려 깨어납니다.
**이 대기는 아래 두 가지로 거의 없앨 수 있고, 둘 다 추가 비용이 들지 않습니다.**

**① 로비에서 자동 예열 (이미 켜져 있음)**

사이트를 여는 순간 백그라운드로 `/api/health` 를 찔러 서버를 깨웁니다.
사용자가 닉네임·블라인드를 채워 넣는 20~40초 동안 서버가 일어나므로,
정작 "방 만들기"를 누를 때는 기다릴 일이 거의 없습니다.
아직 깨어나는 중이면 로비 상단에 `서버를 깨우는 중입니다… (최대 1분)` 이 뜹니다.

게임 중에는 WebSocket 이 계속 열려 있어 서버가 잠들지 않습니다. 즉 **첫 접속만** 느립니다.

> **주의: Render 무료 플랜에서는 서버가 잠들면 만들어 둔 방도 사라집니다.**
> 무료 플랜에는 영구 디스크가 없어서, 잠들 때 컨테이너와 함께 `DATA_DIR` 도 통째로 없어집니다.
> (프로세스가 크래시로 재시작되는 정도는 견딥니다 — 그때는 자리와 스택이 복원됩니다.)
> 방을 만들어 두고 한참 뒤에 들어가면 "방을 찾을 수 없습니다"가 뜨는 이유가 이것입니다.
> 아래 ②로 노는 시간대를 깨워 두면 그 시간 안에서는 방이 유지되고,
> 방이 계속 살아 있어야 한다면 영구 볼륨을 붙일 수 있는 Fly.io 를 쓰세요.

**② 노는 시간대에만 미리 깨워 두기 (`.github/workflows/keep-warm.yml`)**

외부 모니터링 서비스 없이 GitHub Actions 로 `/healthz` 를 10분마다 찌릅니다.
공개 저장소에서는 Actions 가 무료이므로 **추가 비용이 없습니다.**

기본값은 한국시간 **18:00~01:00** 입니다. 24시간 내내 찌르지 않는 이유가 있습니다 —
Render 무료 플랜은 월 750 인스턴스-시간을 주는데, 24시간 깨워 두면 730시간이라
이것만으로 한도를 거의 다 씁니다. 노는 시간대만 깨워 두면 월 200시간 남짓이라 여유가 넉넉합니다.

시간대를 바꾸려면 워크플로의 cron 만 고치면 됩니다(항상 UTC 기준, 한국시간 = UTC+9).

```yaml
- cron: '*/10 9-15 * * *'   # 한국시간 18:00~01:00 (기본값)
- cron: '*/10 11-14 * * *'  # 한국시간 20:00~24:00
- cron: '*/10 9-15 * * 6,0' # 주말 저녁만
```

> 참고: 스케줄 워크플로는 저장소에 60일간 아무 활동이 없으면 GitHub 이 자동으로 꺼 버립니다.
> 그때는 Actions 탭에서 다시 켜면 됩니다. 실행 시각도 몇 분씩 밀릴 수 있는데, 예열 용도로는 문제없습니다.

**③ 아예 잠들지 않게 하려면**

Fly.io 는 `auto_stop_machines = "suspend"` 로 두면 몇 초 만에 깨어나고, 영구 볼륨도 붙습니다.
집에 24시간 켜 두는 PC 나 라즈베리파이가 있다면 Cloudflare Tunnel 로 공개하는 것도 무료입니다.
(각 서비스의 무료 한도는 자주 바뀌니 배포 전에 현재 정책을 확인하세요.)

**Fly.io** (`fly.toml` 포함 — 영구 볼륨이 붙어서 재배포에도 방이 살아남습니다)

```bash
fly launch --no-deploy --copy-config
fly volumes create poker_data --size 1
fly deploy
```

**도커 / 직접 운영**

```bash
docker build -t poker . && docker run -p 3000:3000 -v poker-data:/data poker
```

서버 환경변수:

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `3000` | 수신 포트 |
| `DATA_DIR` | OS 임시 디렉터리 | 방 상태 저장 위치. 영구 볼륨을 잡아 주면 재배포에도 보존됩니다. |
| `ALLOWED_ORIGINS` | (전체 허용) | 접속을 허용할 출처. 배포 후에는 `https://<사용자>.github.io` 로 좁히는 것을 권합니다. |
| `ROOM_TTL_HOURS` | `24` | 아무도 없는 방을 정리하기까지의 시간 |
| `DISCONNECT_GRACE_SEC` | `30` | 연결이 끊긴 사람을 자리비움 처리하기까지의 유예 시간. `0` 이면 처리하지 않습니다. |
| `MAX_ROOMS` | `500` | 동시에 유지할 방 수 상한 |
| `ROOMS_PER_IP` | `20` | IP 당 10분간 만들 수 있는 방 수 |

### 2) 화면을 GitHub Pages 에 올리기

1. 저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 바꿉니다.
2. 저장소 **Settings → Secrets and variables → Actions → Variables** 에서
   **`POKER_SERVER_URL`** 을 1단계에서 얻은 서버 주소로 추가합니다.
   예: `https://poker-with-friends.onrender.com`
   - `https://` 로 시작해야 합니다. Pages 는 https 라서 http 서버를 부르면 브라우저가 조용히 차단합니다
     (빌드 단계에서 미리 걸러 냅니다).
   - 이 변수를 비워 두면 서버 없이 도는 **P2P 폴백**으로 빌드되고, 워크플로가 경고를 남깁니다.
3. 푸시하면 `.github/workflows/pages.yml` 이 테스트 → 빌드 → 배포를 수행합니다.
   (`main` 으로 합친 뒤에는 워크플로의 브랜치 목록에서 작업 브랜치 줄을 지워도 됩니다.)
4. `https://<사용자>.github.io/<저장소>/` 에서 방을 만들고, **🔗 초대 링크 복사**로 나온
   `.../room.html#ABC123` 링크를 친구에게 보내면 됩니다.

5. 서버의 `ALLOWED_ORIGINS` 를 `https://<사용자>.github.io` 로 좁혀 두면 남이 내 서버를 쓰는 것을 막을 수 있습니다.

### 로컬에서 돌려보기

```bash
npm install
npm start          # http://localhost:3000 — 화면과 서버를 한 곳에서 서빙
```

Pages 배포본과 똑같은 구성(정적 화면 ↔ 별도 서버)을 확인하려면 터미널 두 개를 씁니다.

```bash
npm start                        # 1번: 중앙 서버 (3000)
npm run preview                  # 2번: 정적 빌드 미리보기 (4000)
# 그리고 http://localhost:4000/index.html?mode=server&server=http://localhost:3000 접속
```

URL 옵션으로 언제든 바꿔 볼 수 있습니다.

| 옵션 | 뜻 |
| --- | --- |
| `?server=https://...` | 다른 중앙 서버로 붙어 보기 |
| `?mode=p2p` | 서버 없이 P2P 폴백으로 돌려 보기 |

외부의 친구를 임시로 부르려면 터널을 써도 됩니다.

```bash
npx localtunnel --port 3000        # 또는 ngrok http 3000
```

## 게임 규칙 / 구현 범위

- 텍사스 홀덤 **노리밋**, 최대 9인.
- 딜러 버튼 자동 이동, SB/BB 자동 포스팅, 헤즈업일 때는 버튼이 SB이며 프리플랍 선액션입니다.
- 프리플랍에는 BB에게 옵션(체크/레이즈)이 주어집니다.
- 최소 레이즈는 직전 레이즈 폭 이상이어야 하며, 짧은 올인은 액션을 다시 열지 않습니다(정식 룰).
- 올인/사이드 팟/무승부 분배(남는 칩은 버튼 다음 자리부터)를 자동 계산합니다.
- 액션 가능한 사람이 1명 이하가 되면(올인 상황) 한 박자 쉬었다가 겨루는 사람들의
  홀카드를 **먼저 공개**하고, 그 뒤에 남은 보드를 한 장씩 오픈합니다. 실제 테이블에서
  올인 콜이 나오면 카드를 눕히고 보드를 보는 것과 같은 순서입니다.
- 쇼다운에서는 참여자 카드와 족보가 공개되며, 잠시 후 다음 핸드가 자동으로 시작됩니다(방장이 "자동 진행"을 끄면 수동).
- 핸드가 끝나는 순간 결과 화면이 크게 뜹니다. 공개된 카드를 가리지 않도록 다음 핸드가 시작되기 전에 스스로 물러납니다.
- 제한시간을 넘기면 자동으로 체크(가능할 때) 또는 폴드 처리합니다.
- 새로고침하거나 잠깐 끊겨도 같은 자리·같은 홀카드로 복귀합니다(방마다 브라우저에 토큰 저장).
- 연결이 **30초 이상** 끊긴 사람은 자동으로 자리비움 처리되고, 진행 중인 핸드에서는 폴드됩니다.
  그 안에 돌아오면 아무 일도 없었던 것처럼 이어서 하고, 자동으로 비워진 자리는 재접속하면 다시 참가 상태가 됩니다.
- 파산했거나 칩이 필요하면 **💰 칩 추가**로 리바이할 수 있습니다(핸드 진행 중에는 불가).

### 자리 정리

연결이 끊긴 사람은 **30초 뒤에 자동으로 자리비움 처리됩니다.** 진행 중인 핸드를 붙잡고 있었다면 폴드되고
다음 사람으로 넘어가므로, 끊긴 사람 때문에 게임이 멈추지 않습니다. 자리와 스택은 그대로 남아 있어서
**돌아오면 자동으로 다시 참가**합니다(직접 고른 자리비움은 돌아와도 유지됩니다). 방장이 끊기면 남은 사람이
게임을 이어갈 수 있도록 방장만 넘어가고 자리는 지켜 줍니다. 새로고침이나 잠깐의 네트워크 끊김으로
곧바로 빠지지 않게 하려는 유예 시간이고, `DISCONNECT_GRACE_SEC` 로 조절합니다.
끊긴 자리에는 남은 시간이 `연결끊김 42초` 처럼 표시됩니다.

핸드가 진행 중일 때는 폴드만 시키고 자리는 남겨 두었다가, **핸드가 끝난 뒤에 실제로 뺍니다.**
진행 중에 자리를 지워 버리면 그 사람이 팟에 넣은 칩이 정산에서 사라지기 때문입니다.

### 방장 도구

상단 **⚙ 방장 설정**(방장에게만 보입니다)에서 세 가지를 할 수 있습니다.

| 기능 | 동작 |
| --- | --- |
| **블라인드 올리기** | SB/BB 를 직접 입력하거나 `×1.5 ×2 ×3` 프리셋으로 채운 뒤 적용합니다. **핸드 도중이면 다음 핸드부터** 적용되고(진행 중인 판의 블라인드를 바꾸면 정산이 꼬입니다), 그때까지는 배지에 `SB 1 / BB 2 → 2/4` 로 예약이 보입니다. |
| **일시정지** | 액션 제한시간이 멈추고 다음 핸드가 자동으로 시작되지 않습니다. 진행 중인 핸드는 없애지 않습니다(팟에 들어간 칩이 붕 뜨기 때문). 재개하면 **멈춘 시점의 남은 시간부터** 이어서 셉니다. 모두의 화면에 `⏸ 일시정지` 배지가 뜹니다. |
| **강퇴** | 핸드 도중이면 폴드 처리하고 자리는 핸드가 끝난 뒤에 뺍니다(나가기와 같은 규칙 — 그래야 그 사람이 팟에 넣은 칩이 사라지지 않습니다). 내보낸 사람은 연결이 끊기고 **같은 링크로 다시 들어올 수 없습니다.** 잘못 눌렀다면 목록 아래 "다시 입장 허용"으로 되돌립니다. |

> 강퇴는 브라우저에 저장된 참가 토큰 기준입니다. 상대가 저장소를 지우고 새 닉네임으로 들어오는 것까지 막지는 못합니다(친구들끼리 쓰는 방을 전제로 한 기능입니다).

### 편의 기능

- 카드 랭크는 `T` 대신 **10** 으로 표기합니다.
- 단축키: `F` 폴드 / `C` 콜·체크 / `R` 레이즈
- **내 차례 표시**: 화면 가장자리 금색 글로우 + 남은 시간 숫자 카운트다운, 10초 아래로 남으면 붉게 재촉
- 액션 중인 좌석 아래에도 제한시간 게이지가 흘러서, 지금 누가 고민 중인지 한눈에 보입니다
- 다른 탭을 보고 있으면 탭 제목이 `⏰ 내 차례! (12초)`로 깜빡이고, 알림을 허용했다면 데스크톱 알림도 뜹니다
- 내 차례가 오면 짧은 알림음
- 진행 기록 + 간단한 채팅
- **채팅창 크기 조절**: 패널 손잡이를 끌면 넓은 화면에서는 좌우 너비가, 좁은 화면(모바일)에서는 위아래 높이가 바뀝니다. 더블클릭하면 기본 크기로 돌아가고, 손잡이에 포커스한 뒤 방향키(+`Shift`)로도 조절할 수 있습니다. 크기는 브라우저에 저장되어 다음 접속에도 유지되며, 모바일에서는 `▾` 버튼으로 접었다 펼 수 있습니다(접은 동안 새 기록이 오면 버튼이 초록으로 표시됩니다).
- 애니메이션은 OS 의 "동작 줄이기(prefers-reduced-motion)" 설정을 따릅니다
- 모바일 화면 대응 (좌석이 인원 수에 맞춰 자동 배치)
- **액션 바는 가로로 눕혀서** 세로 길이를 아낍니다. '내 패'와 남은 시간이 한 줄, 베팅 단위 토글과 금액 입력이 한 줄로 붙고, 퀵 버튼은 줄바꿈 대신 가로로 스크롤됩니다. 폰을 눕히면(가로 모드) 채팅창이 오른쪽으로 가고 폴드·콜·레이즈 버튼이 베팅 컨트롤 옆에 붙습니다.
- 액션 바가 커져 자리가 부족하면 채팅창이 저장된 크기 안에서 잠시 줄어들어, 테이블이 눌리지 않습니다.

## 프로젝트 구조

```
src/poker.js       52장 덱, 암호학적 셔플, 5~7장 핸드 평가기
src/table.js       테이블 상태 머신 (블라인드·베팅 라운드·사이드 팟·쇼다운)
src/protocol.js    클라이언트 메시지 처리 규칙 (서버 모드와 P2P 폴백이 공유)
src/server.js      중앙 서버 — 방 API + WebSocket 브로드캐스트 + CORS + 정적 서빙
src/store.js       방 상태 디스크 저장/복원 (재시작 대비)
public/net.js      전송 계층 — WebSocket / WebRTC(P2P) 를 같은 인터페이스로 감춘다
public/            로비(index) · 테이블(room) 화면과 스타일
scripts/           정적 빌드 및 미리보기
test/              엔진 단위 테스트 + 랜덤 봇 시뮬레이션 + 서버 통합 테스트
.github/workflows/ GitHub Pages 자동 배포 + 서버 예열(keep-warm)
```

`src/` 의 엔진 세 파일은 Node 와 브라우저 양쪽에서 그대로 동작하도록 작성되어 있어서
(난수는 Node `crypto` / WebCrypto 를 알아서 골라 씁니다), 중앙 서버와 P2P 폴백이 **완전히 같은 게임 로직**을 씁니다.

### 통신 규약

전송 수단(WebSocket `/ws` 또는 WebRTC 데이터 채널)과 무관하게 메시지는 동일합니다.

참가자 → 딜러(서버 또는 방장): `join` · `action`(fold/check/call/raise/allin) · `start` · `sitout` · `addChips` · `autoNext` · `chat` · `leave`
딜러 → 참가자: `joined` · `state`(받는 사람 시점으로 남의 홀카드를 가린 전체 상태) · `error` · `fatal`

## 테스트

```bash
npm test           # 엔진 + 서버 전체
npm run test:engine
npm run test:server
```

엔진:

- 핸드 평가(로열 플러시, 휠 스트레이트, 키커 비교 등)
- 셔플 무작위성 및 카드 중복 검사
- 블라인드 포스팅·액션 순서·BB 옵션·최소 레이즈 검증
- 사이드 팟 및 스플릿 정산
- 연결 끊김 유예 시간(자동 폴드·자리비움, 재접속 시 자동 복귀, 직접 고른 자리비움 유지)
- 실시간 완성 패 계산(프리플랍 조합, 플랍 이후 족보와 사용된 5장)과 본인에게만 노출되는지 여부
- 연결 끊김 시 유예 후 자동 자리비움·폴드, 유예 안에 복귀하면 아무 일도 없음, 방장 승계
- **핸드 도중 퇴장해도 팟의 칩이 사라지지 않는지** (자리를 즉시 지우면 칩이 증발하던 문제)
- **랜덤 봇 5명이 300핸드**를 돌리며 칩 총량 보존·음수 스택 없음·규칙 위반 없음 확인

서버(실제로 포트를 열고 HTTP·WebSocket 으로 붙어서 확인):

- 방 생성 시 설정값 정규화(SB > BB, 최대 인원 초과 등)와 없는 방 404
- CORS 허용/차단, 프리플라이트 응답, 허용되지 않은 출처의 WebSocket 거절
- 두 명 동시 접속 시 상태 방송, 방장 권한 검사
- 연결이 끊겨도 자리와 스택이 남는지
- **디스크에 저장한 방을 재시작 후 복원**하는지

여기에 더해 실제 브라우저 두 개(별도 컨텍스트 = 다른 기기)로 Pages ↔ 서버 교차 출처 시나리오를 돌려
방 생성 → 초대 링크 입장 → 핸드 진행 → 새로고침 복귀 → **방장이 창을 닫아도 게임이 계속되는 것**까지 확인했습니다.
연결 끊김 자동 처리와 내 차례 표시는 브라우저 두 대를 붙여 놓고 소켓을 강제로 끊거나
탭을 백그라운드로 돌려서 확인했습니다.

## 참고

방 데이터(자리·이름·스택)는 서버의 `DATA_DIR` 에만 저장되고, 아무도 접속하지 않은 상태로
`ROOM_TTL_HOURS`(기본 24시간)가 지나면 정리됩니다. 진행 중이던 핸드는 재시작 시 복원되지 않고
대기 상태로 돌아갑니다 — 스택은 그대로입니다.

계정도 비밀번호도 없습니다. 브라우저에 저장된 임의의 토큰이 곧 자리의 열쇠이므로,
초대 링크를 아는 사람은 누구나 들어올 수 있습니다.
실제 돈이 오가지 않는, 친구들끼리 즐기는 용도입니다.
